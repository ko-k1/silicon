# A14 / iOS 27.2 (24B119) differential baseline

- Date: 2026-11-11
- Target manifest: `targets/manifests/iphone12mini-ios27.0.1.yaml`
- Cases: `CASE-0004` (differential baseline), `CASE-0002` (advisory register)
- Status: offline build-artifact and first-pass function differential; no CVE-to-function attribution and no device runtime measurement

## Scope

This report records what differs between the iPhone 12 mini (`iPhone13,1`, A14/T8101) iOS 27.0.1 build 24A446 and iOS 27.2 build 24B119 restore images, and which 27.2 advisory components are plausible candidates for later binary analysis. It covers BuildManifest metadata, the release kernelcache, a first normalized function diff of `com.apple.kernel`, the AVE2 and ANE kexts, SPTM, TXM, and public Apple advisories.

It does not map a CVE to a changed function, demonstrate exploitability, or claim a PPL/SPTM/TXM bypass. Exploit chains, kernel read/write primitives, patch offsets, persistence, and protection-disablement procedures are out of scope.

## Manifest differential

57 of 95 BuildManifest component entries differ and 38 are identical. No keys were added or removed. The change set contains 56 digest changes plus one path-only change (`BasebandFirmware`), with no payload-byte conclusion drawn from the path change alone.

Changed entries include:

- `KernelCache`
- `Ap,SecurePageTableMonitor` and `Ap,RestoreSecurePageTableMonitor`
- `Ap,TrustedExecutionMonitor` and `Ap,RestoreTrustedExecutionMonitor`
- `SEP`, `iBoot`, `LLB`, `iBEC`, `iBSS`, and `DeviceTree`
- the OS and Cryptex volumes and their trust-cache entries

The mix of changed and unchanged components is not a uniform rebuild signature: 38 entries, including several kexts and device drivers, remain identical.

## Function-level differential

`com.apple.kernel` was extracted from each kernelcache, disassembled with `llvm-objdump`, and symbolized with `ipsw kernel symbolicate` and the matching symbolicator signature set.

| Metric | 24A446 | 24B119 |
|---|---|---|
| Function starts | 20,873 | 20,897 |
| Functions with instructions | 20,872 | 20,896 |
| Exact-normalized matches | - | 13,045 |
| Shape-normalized matches | - | 20,399 |
| Named at the same start | - | 5,318 |
| Identical | - | 2,246 |
| Constant-only | - | 2,850 |
| Structural | - | 222 |
| Old-only / new-only names | - | 52 / 51 |

Exact normalization masks absolute branch targets and `adrp`/`add` page-offset pairs while preserving small immediates. Shape normalization also masks every immediate. Exact matches are the stronger identity signal; shape matches can be inflated by layout-dependent address materialization.

The 222 structural names are a candidate inventory, not an attribution. They include IPC and port paths (`ipc_kmsg_copyin_from_user`, `ipc_is_valid_exception_port`, `ipc_right_lookup_read`, `set_exception_ports_validation`), VM paths (`vm_fault_internal`, `vm_map_remap`, `vm_object_update`, `vm_object_iopl_request`), process and exception paths (`task_create_internal`, `thread_set_state_internal`, `exception_deliver`, `posix_spawn`, `forkproc`), filesystem paths (`fsctl_internal`, `renameat_internal`, `vn_open_auth`), and networking paths (`necp_client_parse_parameters`, `pf_test_rule`, `bpfdetach`, `uipc_send`). No function is mapped to a CVE.

The two triaged kexts also change. `AppleAVE2` changes from 913.43.1 to 913.64.1 with 2,995/2,998 function starts, 1,222 exact-normalized matches, and 2,963 shape-normalized matches. Its vtable comparison maps 45 slots: 21 unchanged, 24 constant-only, and 0 structural. `AppleH11ANEInterface` changes from 10.19.6 to 10.102.4 with 4,902/5,043 starts, 3,080 exact matches, and 4,662 shape matches. Its vtable comparison maps 737 slots: 417 unchanged, 265 constant-only, and 55 structural across 34 unique target pairs; ANE also adds three classes. Vtable counts skip external or unmapped targets, so they are not a complete method inventory. 47 of 267 `ipsw` kext records change version; none are added or removed. The MH_FILESET has 250 entries, so the two kext counts are not interchangeable.

The earlier 1,361/1,382 count was an undercount. `ipsw` and an independent `LC_FUNCTION_STARTS` decode both give 20,873/20,897.

The 27.2 advisory has 162 CVEs in the iPhone 11-and-later range and one limited to iPhone 15 Pro and later. The 15 Kernel CVEs are mostly use-after-free, out-of-bounds, type-confusion, race, and memory-integrity issues. None is labelled by Apple as a PPL/SPTM/TXM bypass.

The 27.2 CVE set is disjoint from the 163 CVEs in the iOS 27 advisory. The 27.2.1 advisory adds nine CVEs, also disjoint from 27.2, so 24B119 is not the latest patch level as of 2026-11-11.

## Counter-evidence and alternative explanations

- 27.2 is a feature release; many binary changes are unrelated to security fixes.
- A digest change can reflect a version string, layout change, or non-security bug fix.
- An `LC_UUID` change does not prove a code change; the normalized diff narrows the candidate set but does not prove semantics.
- A structural function-hash difference can reflect compiler layout, function splitting, or a changed call target as well as a security fix.
- Advisory membership is not proof that 24A446 was vulnerable or that 24B119 fixes the issue on A14.
- An unchanged kext does not prove the named component is unaffected; the fix may be in the kernel proper or another image.
- Apple may revise the 27.2 advisory. The CSAF SHA-256 is recorded so a revision is detectable.

## What is established

- The 24B119 iPhone13,1 image is a different build from 24A446 at the manifest and binary levels.
- 57 of 95 manifest component entries differ; no keys were added or removed.
- The release kernelcache changes build and grows by 278,528 decompressed bytes; 207 of 250 kext UUIDs change.
- The first normalized kernel diff finds 13,045 exact matches and 222 structurally different named functions; it does not map them to CVEs.
- AppleAVE2 and AppleH11ANEInterface change version and function-level layout; 47 of 267 `ipsw` kext records change version.
- SPTM changes from 820.0.22 to 820.40.24; TXM keeps 217.0.2 but has a different UUID and hash.
- The 24B119 SPTM and TXM payload hashes match the 27.2 BuildManifest installed-component digests.
- The 27.2 advisory introduces 163 CVEs disjoint from the 27.0 set, including 15 Kernel and 26 WebKit entries.
- 27.2.1 adds nine further CVEs not present in 24B119.

## What remains unknown

- Which changed functions, if any, correspond to the 15 Kernel CVEs.
- Whether any listed CVE is reachable on A14 / 24B119.
- Whether the changed AVE2 or ANE functions contain the corresponding fixes.
- What the 222 structural kernel changes mean semantically; no source-level or call-graph equivalence was established.
- What changed in WebKit and ImageIO; their binaries are inside encrypted cryptexes.
- Whether the target device is running 24A446 and whether SPTM/TXM is active and enforcing.

## Limitations

- No device was available; runtime protection state and installation are unmeasured.
- The kernel image is stripped; changed functions were not attributed to source symbols or CVEs.
- Function starts come from `ipsw` and are not guaranteed semantic boundaries; structural hash differences can reflect compiler layout or call-target changes.
- Symbolicator coverage is partial: 5,318 names matched at the same start, while 52 old-only and 51 new-only names remain unmatched.
- The earlier 1,361/1,382 function-start count was an undercount; `EVD-0027` records the corrected 20,873/20,897 count.
- Kext UUID changes are build-identity changes, not proof of security-relevant code changes.
- The 27.2 advisory is documentary evidence; CVE membership does not establish reachability on A14.
- WebKit, ImageIO, and most userspace components live in encrypted system-volume cryptexes and were not inspected at the binary level.
- Only the iPhone13,1 customer restore identity was compared.
- 24B119 predates the nine 27.2.1 fixes.
- Raw IPSWs, manifests, and extracted payloads are not committed; hashes identify the inputs.

## Next steps

1. Disassemble the highest-value structural candidates in both builds, starting with IPC/exception-port and VM paths.
2. Use the AVE2/ANE class vtables to map changed functions to class methods and inspect their call sites.
3. Map changed functions to the 15 Kernel CVEs only where strings, cross-references, or other evidence support attribution.
4. Keep WebKit and ImageIO out of binary conclusions unless a lawful unencrypted source becomes available.
5. Re-check the advisory register before treating 24B119 as current.
