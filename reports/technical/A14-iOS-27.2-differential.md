# A14 / iOS 27.2 (24B119) differential baseline

- Date: 2026-11-11 (updated 2026-11-12)
- Target manifest: `targets/manifests/iphone12mini-ios27.0.1.yaml`
- Cases: `CASE-0004` (differential baseline), `CASE-0002` (advisory register)
- Status: offline build-artifact and first-pass function differential; no CVE-to-function attribution and no device runtime measurement

## Scope

This report records what differs between the iPhone 12 mini (`iPhone13,1`, A14/T8101) iOS 27.0.1 build 24A446 and iOS 27.2 build 24B119 restore images, and which 27.2 advisory components are plausible candidates for later binary analysis. It covers BuildManifest metadata, the release kernelcache, a first normalized function diff of `com.apple.kernel`, the AVE2 and ANE kexts, SPTM, TXM, and public Apple advisories.

It does not map a CVE to a changed function, demonstrate exploitability, or claim a PPL/SPTM/TXM bypass. Exploit chains, kernel read/write primitives, patch offsets, persistence, and protection-disablement procedures are out of scope.

## Manifest differential

57 of 95 BuildManifest component entries differ and 38 are identical. No keys were added or removed. The change set contains 56 digest changes plus one path-only change (`BasebandFirmware`), with no payload-byte conclusion drawn from the path change alone.

Changed entries include:

- `KernelCache`
- `Ap,SecurePageTableMonitor` and `Ap,RestoreSecurePageTableMonitor`
- `Ap,TrustedExecutionMonitor` and `Ap,RestoreTrustedExecutionMonitor`
- `SEP`, `iBoot`, `LLB`, `iBEC`, `iBSS`, and `DeviceTree`
- the OS and Cryptex volumes and their trust-cache entries

The mix of changed and unchanged components is not a uniform rebuild signature: 38 entries, including several kexts and device drivers, remain identical.

## Function-level differential

`com.apple.kernel` was extracted from each kernelcache, disassembled with `llvm-objdump`, and symbolized with `ipsw kernel symbolicate` and the matching symbolicator signature set.

| Metric | 24A446 | 24B119 |
|---|---|---|
| Function starts | 20,873 | 20,897 |
| Functions with instructions | 20,872 | 20,896 |
| Exact-normalized matches | - | 13,045 |
| Shape-normalized matches | - | 20,399 |
| Named at the same start | - | 5,318 |
| Identical | - | 2,246 |
| Constant-only | - | 2,850 |
| Structural | - | 222 |
| Old-only / new-only names | - | 52 / 51 |

Exact normalization masks absolute branch targets and `adrp`/`add` page-offset pairs while preserving small immediates. Shape normalization also masks every immediate. Exact matches are the stronger identity signal; shape matches can be inflated by layout-dependent address materialization.

The 222 structural names are a candidate inventory, not an attribution. They include IPC and port paths (`ipc_kmsg_copyin_from_user`, `ipc_is_valid_exception_port`, `ipc_right_lookup_read`, `set_exception_ports_validation`), VM paths (`vm_fault_internal`, `vm_map_remap`, `vm_object_update`, `vm_object_iopl_request`), process and exception paths (`task_create_internal`, `thread_set_state_internal`, `exception_deliver`, `posix_spawn`, `forkproc`), filesystem paths (`fsctl_internal`, `renameat_internal`, `vn_open_auth`), and networking paths (`necp_client_parse_parameters`, `pf_test_rule`, `bpfdetach`, `uipc_send`). No function is mapped to a CVE.

The two triaged kexts also change. `AppleAVE2` changes from 913.43.1 to 913.64.1 with 2,995/2,998 function starts, 1,222 exact-normalized matches, and 2,963 shape-normalized matches. Its vtable comparison maps 45 slots: 21 unchanged, 24 constant-only, and 0 structural. `AppleH11ANEInterface` changes from 10.19.6 to 10.102.4 with 4,902/5,043 starts, 3,080 exact matches, and 4,662 shape matches. Its raw vtable comparison maps 737 slots: 417 unchanged, 265 constant-only, and 55 raw structural across 34 unique target pairs; ANE also adds three classes. The 55 raw slots are not a method-change count: exact-start name-aware classification gives 11 same-name/same-slot rows with changed bodies (7 unique target pairs), 8 one-sided-name rows (4 unique pairs), and 36 both-unnamed rows (23 unique pairs); function-start alignment then resolves seven pairs as slot reordering (`EVD-0034`). Vtable counts skip external or unmapped targets, so they are not a complete method inventory. 47 of 267 `ipsw` kext records change version; none are added or removed. The MH_FILESET has 250 entries, so the two kext counts are not interchangeable.

The earlier 1,361/1,382 count was an undercount. `ipsw` and an independent `LC_FUNCTION_STARTS` decode both give 20,873/20,897.

## Targeted follow-up

Both exception-port validation functions add a `com.apple.security.cs.debugger` entitlement query in 27.2: `ipc_is_valid_exception_port` (93 -> 99 instructions) and `set_exception_ports_validation` (178 -> 184). The string is absent from the 24A446 kernel and present once in 24B119. Both functions already accept `com.apple.private.set-exception-port`, so the change broadens the accepted entitlement set rather than narrowing it. The helper used by `ipc_is_valid_exception_port` is shape-identical between builds. No fix or security-impact claim is made.

The same debugger-entitlement query appears in `thread_set_state_internal` (324 -> 348 instructions). In 27.2 three access-check paths query `com.apple.security.cs.debugger` in addition to `com.apple.private.thread-set-state`; 24A446 queries only the private entitlement. The combined branch denies in the path where both queries succeed, so the net authorization effect is not established from the decompilation alone. The new function also calls an unidentified policy routine at `0xfffffff00aa1aedc` when bit 0 of its flag argument is set, returning 8 on failure. The later IPC policy-violation denial path is routed through a wrapper at `0xfffffff00a1b8958`; no semantic conclusion is drawn from that refactor.

Two VM functions were decompiled to narrow structural candidates. `vm_map_remap` (395 -> 449 instructions) adds an early rejection when flag bit 8 is set and either flag bit 43 is set or the value at `*param_9` or `*param_10` exceeds 1. It also clears bits 7 and 16 of a VM entry's flag word (mask `0xfffeff7f`) when flag bit 8 is set and entry bit 7 is set. `vm_object_update` (1029 -> 1157 instructions) adds `vm_object_pl_req_begin`/`vm_object_pl_req_end` accounting on a 32-bit counter at object byte offset `0xe8`, with overflow and underflow panics, and clears bit 0 of object byte offset `0x74` when the counter reaches zero. The 24A446 function has neither the strings nor the counter logic. These are concrete code changes; their security relevance and any CVE relationship remain unestablished.

`AppleAVE2` adds three named validation routines that are absent from the 24A446 symbol map and whose 27.2 `__os_log` anchors are absent from the 24A446 binary:

| Routine | 27.2 start | Instructions | Callers |
|---|---|---:|---|
| `AVE_HEVC_CheckVPSExtBounds` | `0xfffffff008421158` | 310 | `AVE_HEVC_CheckInfo`, `AVE_Client_CheckDMVInfo`, `AVE_Client_CheckGGMInfo`, `AVE_Client_CheckMCTFInfo`, `AVE_Client_CheckLRMEInfo` |
| `AVE_Client_CheckMCTFInfo` | `0xfffffff008423b1c` | 737 | `AVE_Client_CheckInfo` |
| `AVE_Client_CheckLRMEInfo` | `0xfffffff0084246a0` | 571 | `AVE_Client_CheckInfo` |

The routines contain unsigned range checks with limits including `0x40`/`0x41` (VPS), `0x2`/`0x8`/`0x6`/`0xf`/`0x10`/`0x1`/`0x3f`/`0x41`/`0x11`/`0xd`/`0x3`/`0x15` (MCTF), and `0x2`/`0x7`/`0x8`/`0x6`/`0xf`/`0x10`/`0x1`/`0x3f`/`0x41`/`0x11`/`0xd`/`0x15` (LRME). The decompiled MCTF and LRME routines also bound the layer number to 1..2, the sub-layer count to 1..7, the temporal-layer count to <8, several VPS count fields, the SPS count, object offset `0x5e0` to <3, and object offset `0x420` to <`0x15`. These labels come from the decompiled control flow and adjacent log strings; some offsets are shared across different error branches. Their names come from symbolicator signatures anchored on new log strings, not local symbols; same-virtual-address old functions are not confirmed counterparts. The 27.2 advisory lists six AVEVideoEncoder CVEs described as one out-of-bounds read and five out-of-bounds writes addressed with improved input validation or bounds checking. The correlation is temporal and functional, not a CVE attribution.

The earlier ANE symbol-map warning was rechecked. At `0xfffffff00a8e69e8` the xnu-only signature map names `PMSettingObject::pmSettingObject`, while the full xnu+kext signature map at the same commit names `IOUserClient::sendAsyncResult`, matching the 27.0 function at `0xfffffff00a8a6888`. The earlier claim that the map lacks `sendAsyncResult` is true only for the xnu-only map; this is a signature-set coverage artifact. Overlaying the xnu-only new-build names on the full map reproduces the earlier 16 same-slot-different-name rows exactly; they are not 16 method replacements. Function-start alignment of the 55 structural rows (32 unique old and 34 unique new functions) resolves seven pairs as slot reordering, including `ANEHWDevice::ReleaseDebugWorkProcessor` and `ANEHWDevice::ANE_RegisterDebugWorkProcessor` moving from slots 225/226 to 229/230. Seven pairs remain same-name/same-slot body changes: `ANEClientHintsUserClient::setProperties`, `ANEDriver::start`, `ANEHWDevice::start`, `ANEHWDevice::stop`, `ANEHWDevice::dartUnmapMemoryDescriptor`, `ANEScheduler::free`, and `ANEScheduler::init`. Eighteen old and twenty new functions remain unresolved because they are unnamed and their body hashes are ambiguous or absent. `ANEHWDevice`/`H11ANEIn` grow from 232 to 236 slots and `ANEDeviceInterface` from 222 to 226, so same-index comparisons after the insertion are spurious. No CVE is mapped.

## Counter-evidence and alternative explanations

- 27.2 is a feature release; many binary changes are unrelated to security fixes.
- A digest change can reflect a version string, layout change, or non-security bug fix.
- An `LC_UUID` change does not prove a code change; the normalized diff narrows the candidate set but does not prove semantics.
- A structural function-hash difference can reflect compiler layout, function splitting, or a changed call target as well as a security fix.
- Advisory membership is not proof that 24A446 was vulnerable or that 24B119 fixes the issue on A14.
- An unchanged kext does not prove the named component is unaffected; the fix may be in the kernel proper or another image.
- Apple may revise the 27.2 advisory. The CSAF SHA-256 is recorded so a revision is detectable.

## What is established

- The 24B119 iPhone13,1 image is a different build from 24A446 at the manifest and binary levels.
- 57 of 95 manifest component entries differ; no keys were added or removed.
- The release kernelcache changes build and grows by 278,528 decompressed bytes; 207 of 250 kext UUIDs change.
- The first normalized kernel diff finds 13,045 exact matches and 222 structurally different named functions; it does not map them to CVEs.
- Both exception-port validation paths add a `com.apple.security.cs.debugger` entitlement query; this broadens the accepted entitlement set.
- `thread_set_state_internal` adds the same debugger entitlement query in three access-check paths; its net authorization effect is not established.
- `vm_map_remap` adds a new rejection condition for flag bit 8 with flag bit 43 or multiple inputs, and clears VM-entry bits 7 and 16 in one path.
- `vm_object_update` adds `vm_object_pl_req_begin`/`end` accounting with overflow and underflow panics.
- AppleAVE2 adds three named range-check routines for HEVC VPS, MCTF, and LRME fields; the six AVEVideoEncoder out-of-bounds CVEs correlate temporally and functionally, but no CVE is mapped.
- AppleAVE2 and AppleH11ANEInterface change version and function-level layout; 47 of 267 `ipsw` kext records change version.
- The ANE raw 55-slot vtable change resolves to 7 unique named changed-body candidate pairs plus unresolved rows; it is not a method-change count.
- SPTM changes from 820.0.22 to 820.40.24; TXM keeps 217.0.2 but has a different UUID and hash.
- The 24B119 SPTM and TXM payload hashes match the 27.2 BuildManifest installed-component digests.
- The 27.2 advisory introduces 163 CVEs disjoint from the 27.0 set, including 15 Kernel and 26 WebKit entries.
- 27.2.1 adds nine further CVEs not present in 24B119.

## What remains unknown

- Which changed functions, if any, correspond to the 15 Kernel CVEs.
- Whether the `vm_map_remap` validation or `vm_object_update` accounting changes address a specific advisory issue.
- Whether any listed CVE is reachable on A14 / 24B119.
- Whether the changed AVE2 or ANE functions contain the corresponding fixes.
- What the 222 structural kernel changes mean semantically; no source-level or call-graph equivalence was established.
- What changed in WebKit and ImageIO; their binaries are inside encrypted cryptexes.
- Whether the target device is running 24A446 and whether SPTM/TXM is active and enforcing.

## Limitations

- No device was available; runtime protection state and installation are unmeasured.
- The kernel image is stripped; changed functions were not attributed to source symbols or CVEs.
- Function starts come from `ipsw` and are not guaranteed semantic boundaries; structural hash differences can reflect compiler layout or call-target changes.
- Symbolicator coverage is partial: 5,318 names matched at the same start, while 52 old-only and 51 new-only names remain unmatched.
- Symbolicator labels are candidate labels. The `PMSettingObject::pmSettingObject` example is a signature-set coverage artifact: it appears with the xnu-only signature set, while the full xnu+kext set names the same address `IOUserClient::sendAsyncResult`.
- The earlier 1,361/1,382 function-start count was an undercount; `EVD-0027` records the corrected 20,873/20,897 count.
- Kext UUID changes are build-identity changes, not proof of security-relevant code changes.
- Vtable slot comparison by index is affected by inherited slots, slot reordering, and symbolicator label errors; the raw 55-slot count is not a method-change count. The revised one-sided and both-unnamed counts depend on the exact-start name rule.
- The 27.2 advisory is documentary evidence; CVE membership does not establish reachability on A14.
- WebKit, ImageIO, and most userspace components live in encrypted system-volume cryptexes and were not inspected at the binary level.
- Only the iPhone13,1 customer restore identity was compared.
- 24B119 predates the nine 27.2.1 fixes.
- Raw IPSWs, manifests, and extracted payloads are not committed; hashes identify the inputs.

## Next steps

1. Finish the AVE2 check-routine review by mapping each branch to the corresponding HEVC/MCTF/LRME field and bound; the current pass records the checks but does not establish which input bug, if any, they address.
2. Treat the remaining 18 old and 20 new ANE functions as unresolved unless a stronger name source or call-site evidence becomes available; do not assign labels from nearest-symbol or slot-index association.
3. Continue the highest-value kernel structural candidates. The exception-port and thread-state changes broaden accepted entitlements, so deprioritize them as fix candidates unless contrary evidence appears. `vm_map_remap` and `vm_object_update` now have concrete observed changes; test whether either aligns with a specific advisory description without asserting attribution.
4. Map changed functions to the 15 Kernel CVEs only where strings, cross-references, or other evidence support attribution.
5. Keep WebKit and ImageIO out of binary conclusions unless a lawful unencrypted source becomes available.
6. Re-check the advisory register before treating 24B119 as current.
